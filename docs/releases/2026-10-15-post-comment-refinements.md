# Post layout, conversations and notification refinements

- Hide humor style labels in feed, detail, recommendations, profile grids, leaderboard rows/podiums and creator previews/editor. Existing style metadata stays compatible with storage and AI variety validation.
- Use square image frames outside detail, a consistent four-line caption area in grid cards and smaller detail typography. Keep recommendation captions at three lines, detail images/captions complete and exported PNG captions unconstrained.
- Group replies beneath their actual parent, oldest-first within each conversation. Top/New orders root comments. New/pending replies highlight and promote the conversation while staying underneath their parent. Missing ancestors are retrieved using the existing signed-in, same-post comment endpoint and cached per viewer/post. Deletion/Ha patches also update ancestor/notification-target caches. Deleted parents keep their replies and @deleted text. Cyclic/cross-post references are rejected or kept as safe roots; visual indentation stops after two levels.
- Account menu now identifies Notifications with a tomato-red unread dot, while retaining the avatar unread count and accessible labels. The Notifications row remains neutral rather than looking selected by default. Read status uses the same existing SWR summary.
- Audited optional direction: WritingMode -> create store -> useCreateController -> generate API -> captionPrompt -> Gemini text part, including regeneration. The direction is also saved in existing generation prompt/context fields. Strengthened system instructions so every option centers on the supplied situation/viewpoint and the default campus/NYC angle cannot replace it. The supplied teamwork example's four outputs all concern a teammate backing the speaker. This is input-path validation and review of supplied real output, not a claim that arbitrary future model outputs pass automatic semantic evaluation.

No database migration or schema/permission change. Validation: npm test (threading, off-page ancestors, deleted/cyclic/cross-post cases and exact English/Chinese/blank/multiline direction forwarding), lint, TypeScript and production build. Actual component fixtures passed 18 page/viewport checks (1280/768/375px) for overflow, hidden labels, caption/image separation, reply nesting/order and unread-dot contrast. Fixtures are read-only examples and do not publish posts, comments or notifications to production.
