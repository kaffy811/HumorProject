# Post details, comments and public previews

`/post/[id]` now uses the shared PostCard in detail mode: complete caption, uncropped image, existing Ha/save/share controls, and an independent comments panel. Desktop comments remain sticky and scroll internally; smaller screens place the composer above the mobile navigation. Keep going shows up to three other hot posts and disappears when none exist. Feed entry records survive route scroll resets so returning restores the actual reading position and loaded pages.

Comments support Top/New snapshot pagination, replies, Ha, author-only deletion and reports. Sending inserts a highlighted optimistic row, patches the same post in all viewer-scoped SWR caches, and triggers the mascot. Failed sends remove the temporary row and restore the original text while preserving text typed during the request. Bodies are plain multiline text, limited to 280 Unicode characters. Server transactions enforce three sends per ten seconds, ownership, same-post replies and retry idempotency. Deleting a comment retains its tombstone for replies to display `@deleted`. Deleting a post removes its comments, comment votes, saves and reports through a database trigger.

Anonymous post pages receive only a 20-character caption excerpt and a URL for a previously stored, low-resolution blurred thumbnail. Full post APIs, media and comments require Google authentication. The original caption/image URL never enters the anonymous page payload. Google returns through the exact `/auth/callback` URL; an HttpOnly cookie holds a validated internal return path, including `#comments`, and survives first-time Profile onboarding.

Open Graph and Twitter use a dedicated 1200×630 PNG: a clear cropped photo, a 60-character caption excerpt with ellipsis, author and logo. The original media URL stays on the server. PNGs are cached in the private `humor-previews` bucket; every public image request checks the active post first, so a deleted post returns 404 rather than a stale CDN image.

Migrations `202610110005_post_comments.sql` and `202610110006_comment_retry_fingerprint.sql` were applied to the designated existing Humor Project database. All added tables retain strict RLS; mutation RPCs are service-only. No authentication or storage protection was relaxed.

Stored locked thumbnails are generated before publishing. Existing rows can be backfilled with `scripts/backfill-post-previews.mjs`, using server-side Supabase credentials supplied through the environment, or the owner-only `/maintenance/previews` screen using the existing deployment configuration. Both approaches skip completed rows and are safe to resume. `HUMOR_MAINTAINER_ID` can override the existing project owner's verified user ID. No credential is embedded in source.
